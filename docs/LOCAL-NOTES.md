# Local edition: architecture, privacy and verification

## One address, one process

`npm start` builds `client/dist`, then runs `server/src/index.js`. Express binds to **127.0.0.1:3000** and serves both React routes (`/`, `/admin`) and all `/api` endpoints. No proxy or second backend port is used. Same-origin API requests are derived from the page's origin; there is no build-time backend URL.

The app is local-only, not a remotely hosted MERN deployment. React and Express remain, while the database/cloud-media dependencies have been replaced by an atomic JSON store and local files. There is no MongoDB requirement in this edition.

The server rejects unexpected Host headers and cross-origin browser requests. It supplies restrictive security headers and a Content Security Policy that permits only same-origin app resources plus local data/blob images. It does not request external fonts, images, analytics or music.

## Storage

`server/src/store.js` loads bundled defaults once for a new installation. It serializes changes through a queue and writes a temporary file followed by rename. Invalid existing data is never silently replaced. Local snapshots include `draft`, `published`, a revision, administrator password hashes, hashed expiring sessions and media metadata. Save/publish compare revisions to reject stale writes.

This is a single-process local store, not a multi-user database. Stop the server before running the administrator CLI or copying/restoring data. Do not run several project copies against the same data directory. A Windows launcher uses this same local server.

Local photos and music live in `data/uploads`. Each upload is limited by size and checked using file signatures; image decoding also has a pixel limit. Photos are re-encoded into WebP originals and separate thumbnails. Invalid processing cleans up partial files. Removing a saved memory reference does not erase the file automatically; remove it from both snapshots before deleting it through the studio.

## Authentication and draft media

Studio passwords are salted and hashed with Node's scrypt. A raw bearer token lives only in React memory and expires after two hours; only its hash is written to the data file. Refresh requires signing in again. Logout revokes the saved session. There are no cross-site cookies and no hardcoded password. Resetting an administrator through the CLI revokes that account's sessions.

Public photos can be read from their local media URL if they are referenced in the currently published local snapshot. Draft-only files require an HMAC-signed link generated by the authenticated studio. These links expire after two hours. Expired links can be renewed by refreshing files/reopening preview. File names are generated identifiers, not user-selected paths.

Anyone with access to your computer and its data folder can read or copy that local data; this is not filesystem encryption. Noindex is not access control. The server itself accepts loopback connections only; a localhost URL cannot be opened on your friend's separate computer. For another computer, copy the project plus desired data and run it there, or request a separate hosted version later.

## API

| Endpoint | Access |
| --- | --- |
| GET `/api/health` | Local readiness and storage status |
| GET `/api/birthday` | Published local snapshot |
| POST `/api/auth/login` | Rate-limited studio login |
| POST `/api/auth/logout` | Authenticated session revocation |
| GET/PUT `/api/admin/draft` | Authenticated draft retrieval/save |
| GET `/api/admin/preview` | Authenticated saved-draft preview |
| POST `/api/admin/publish` | Authenticated revision-checked local publication |
| GET/POST `/api/admin/media` | Authenticated local file listing/upload |
| DELETE `/api/admin/media/:id` | Authenticated, rejects referenced files |
| GET `/api/media/:id/full` | Published file or valid signed preview |
| GET `/api/media/:id/thumbnail` | Published thumbnail or valid signed preview |

The studio saves memory changes and ordering through the complete validated draft. Invalid inputs return field errors; missing authentication returns 401; stale revisions and protected file deletion return 409. JSON requests are limited to 100 KB. API/login/upload rate limits are held in process memory.

## Garden edition — version 4

The new public UI is a brown-and-green storybook garden: greenhouse doors, three wish seedlings with three growth stages, turning leaf notes, a collectible-firefly jar, a woodland cake, real-photo placeholders, future memory ideas, a private paper-boat wish and a letter modal. SVG illustrations are code-native. Scene transitions, gate perspective, butterfly drift, leaf flips, firefly glows, smoke and petal effects use CSS. Themes switch between daylight and moonlight. Motion can be paused; operating-system reduced motion is respected.

The birthday is **2026-10-24** and uses **Asia/Kolkata**. The countdown computes the intended local midnight, updates once per minute and changes to a birthday-day message instead of counting below zero. After the birthday the site remains a keepsake.

`client/src/GardenWidgets.jsx` owns the new interactive components. Components use React state and accessible buttons, with no drag-only or microphone-only requirements. SVG resource identifiers and wish form IDs are scoped with useId to support a studio preview alongside the visitor page.

No past shared memory is fabricated. The gallery accepts real uploads; empty frames are labelled. The memory jar explicitly describes future ideas. The paper-boat textarea is not persisted and makes no network request. Letter text is plain text with paragraph formatting.

## Included audio

`shared/assets/october-light.wav` is an original, deterministic computer-composed instrumental, approximately 98.3 seconds, mono PCM at 22050 Hz. `scripts/compose-october-light.py` is the optional source generator (Python + NumPy). No additional runtime package is required to play the included file.

`shared/assets/music.json` holds its local media metadata. A new local store seeds this asset and its default selection. Existing local data has been explicitly personalised for Anu/Kushal and the given date. Startup restores a missing built-in media file from the master only while that built-in asset remains in the media records. A user who removes its content references and deletes it through the studio is not silently re-subscribed to it.

The normal local media route serves WAV data and HTTP range requests. Music is not autoplayed. The frontend begins at a gentle volume when metadata loads. User-supplied replacement music continues to use the original validated local upload flow.

## Verification

Production build, local-server route checks, automated backend tests and React tests are run for this version. New cases cover seed growth/reset, firefly collection/reset, leaf turning, future memory choices, non-networked private wishes, timezone-aware countdowns, individual candles, the letter modal and click-to-play audio. Existing backend tests cover actual image/audio storage, validation, authentication, draft isolation, publishing, media deletion and corrupted-data protection.

Tests do not substitute for visual inspection on a real phone. No browser-control skill was available, so actual device layout, native audio quality and a real browser PNG download still need a manual check on your PC. The PCM file format/duration/level, real local audio delivery and range requests are checked in this environment. The Windows CMD launcher is reviewed but cannot be executed on Linux.

Node.js compatibility remains unchanged. The launcher can prefer a compatible Program Files Node installation over an older NVM-selected executable for its own window. It does not change your machine's permanent PATH.
